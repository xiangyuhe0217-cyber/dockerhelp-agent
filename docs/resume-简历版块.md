# 简历版块：dockerhelp-agent（对齐「短视频审核后台」那种写法）

> 格式对齐：一句话项目简介 → 技术栈一行 → 个人职责 3~4 条 → 技术亮点 3 条（带数字）。
> 所有数字可在仓库复现，见文末「数字出处」。

---

## 主版本（推荐）

**项目简介**：面向企业 IT 服务台的 Docker 场景智能助手，包含知识检索问答、工单查询与创建、SLA 判定、结案沉淀等功能，基于 LangGraph 编排与混合检索支撑「中文提问 → 英文文档」的跨语言应答与工单闭环。

**技术栈**：Python 3.11、FastAPI、LangGraph、FAISS、BM25(jieba)、SQLite、Redis、Vue 3、SSE、通义千问（qwen-plus / text-embedding-v3 / gte-rerank）

**个人职责**

- 负责混合检索链路开发，基于结构感知切片与「向量 + BM25」双路召回，通过 RRF 融合与文档黑名单过滤提升跨语言检索质量，并搭建 65 条评测集与 5 项指标基线。
- 设计 LangGraph 路由式 Agent，用确定性意图分流「纯知识问答 / 工具编排」两条链路，基于 interrupt 与 checkpoint 实现写操作人工确认，保证暂停恢复时副作用不重复。
- 设计三层记忆机制，会话快照、长期事实与审计日志分离，记忆块注入 system prompt 而非拼接消息，支持跨会话回忆客户等级与产品版本。
- 建设数据闭环与降级策略，工单结案自动转为知识库案例并复用同一套索引，知识库未命中时降级网页搜索并强制标注来源。

**技术亮点**

- 混合检索在 65 条中文评测集上 hit@5 由 0.650 提升至 0.767、Recall@5 达 0.533，P50 延迟 215ms；11 组消融验证跨语言重排为负收益（-6.6pp）并据此否决。
- interrupt + checkpoint 构建写操作闸门，拒绝时零副作用写入；三项运行中间件使单次问答 token 消耗由 17,208 降至 5,138（-70%），并配套 35 项单测 + 9 项 API 验收。
- 工单结案自动沉淀为知识库案例并复用同一索引，中文案例检索由 Top-10 外提升至 Top-1，实现「问答 → 处置 → 沉淀 → 再检索」闭环。

## 极简版（版面紧张时，删到 3+2）

**项目简介**：面向企业 IT 服务台的 Docker 场景智能助手，基于 LangGraph 编排与混合检索，实现中文提问到英文文档的跨语言应答与工单闭环。

**技术栈**：Python 3.11、FastAPI、LangGraph、FAISS、BM25、Redis、Vue 3、SSE

**个人职责**

- 构建混合检索链路：结构感知切片 + 向量/BM25 双路召回 + RRF 融合 + 文档黑名单，配套 65 条评测集与指标基线。
- 基于 LangGraph 实现路由式 Agent 与写操作人工确认（interrupt + checkpoint），设计三层记忆与运行中间件。
- 打通工单结案到知识库的沉淀闭环，并实现知识库未命中时的网页搜索降级。

**技术亮点**

- hit@5 由 0.650 提升至 0.767，P50 215ms；11 组消融验证重排为负收益（-6.6pp）并否决。
- token 消耗降低 70%（17,208 → 5,138）；35 项单测 + 9 项 API 验收全通过。

## 为什么这么写（每条句子的设计意图）

| 位置 | 你给的范例 | 我这版 | 意图 |
|---|---|---|---|
| 项目简介 | 面向运营人员的短视频审核后台… | 面向企业 IT 服务台的…助手 | **先说"给谁用 + 干什么"**，不堆技术名词 |
| 个人职责 1 | 负责上传链路，基于 MinIO 设计分片上传 | 负责混合检索链路，基于结构感知切片 + 双路召回 | **"负责 X，基于 Y 实现 Z"** 句式，技术点必须落到具体机制 |
| 个人职责 2 | 设计审核引擎，通过 MQ 异步解耦 | 设计路由式 Agent，用 interrupt + checkpoint 做确认 | 同上，动词开头（负责/设计/建设） |
| 技术亮点 | 带 99%+ / 1000+ QPS / <10ms | 带 hit@5 / token / Top-1 | **每条亮点必须有数字，且是能复现的数字** |

**三个写作原则**

1. **职责写机制，亮点写数字**。职责回答"你做了什么"，亮点回答"结果如何"。
2. **技术栈按"语言 → 框架 → 存储 → 前端 → 模型"排序**，一眼能扫完。
3. **每条不超过两行**。范例里每条都很短，长句会让 HR 跳过。

## 不要写什么（重要）

| 别写 | 原因 |
|---|---|
| ❌ QPS / 成功率 | 我们没有压测数据，而且当前是**单进程 + 全局锁**，写"高并发"一问就穿 |
| ❌ Gradio / Milvus / Chroma | 都是历史方案，已弃用（详见 docs/deep-dive.md 第五节） |
| ❌ "基于 RAG 实现智能问答" | 太泛，任何人都能写；要写**具体机制**（RRF、结构感知切片、黑名单） |
| ❌ 编造的准确率 | 面试官会让你现场复现，复现不出来比不写更糟 |

## 两个可能被追问的点，先想好

**Q：为什么不用重排？**
> 做了，E4 加完 hit@5 从 0.733 掉到 0.667。中文 query 对英文文档做 cross-encoder，
> 跨语言分数噪声大，还把原本排对的压下去了。所以我保留消融数据但没进最终链路。

**Q：215ms 是指什么？**
> 单题平均检索延迟，含 embedding 网络往返。纯计算部分在 20ms 量级（BM25 全程 21ms）。
