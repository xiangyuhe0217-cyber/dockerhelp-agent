# W7.2 修复与增强：消息渲染 bug · 网页搜索降级

> 你反馈的三个问题，逐条处理：
> ① 用户提问不显示 → **前端真 bug**（`ref` 塞数组）
> ② 知识库没结果就只会说"没找到" → 加**两级降级**，自动去网上搜
> ③ "确认提交"却走了 RAG 模式、调不了工具 → 补路由关键词

## 一、用户提问不显示（真 bug）

### 原因

```js
// ❌ 错误写法
const msg = ref({ role: 'user', text: q })
messages.value.push(msg)
```

Vue 3 有一条容易被忽略的规则：**ref 被放进数组/Map 时不会自动解包**（只在对象属性上解包）。
所以模板里 `v-for="m in messages"` 拿到的 `m` 是 Ref 对象本身，`m.text` 是 `undefined`。

助手消息之所以"看起来没问题"，是因为它在另一个分支里被当普通对象处理了——属于巧合。

### 修法

推**普通对象**，然后通过数组代理按下标改（流式追加必须走代理，否则不触发更新）：

```js
messages.value.push({ role: 'user', text: q })
const idx = messages.value.length
messages.value.push({ role: 'assistant', text: '', meta: '' })
// 流式时：
const bubble = () => messages.value[idx]
bubble().text += delta      // ✅ 通过响应式代理修改
```

> 教训：**Vue 里"数据改了但界面没变"九成是响应式丢失**——要么是 ref 没解包，
> 要么是改了原始对象而不是代理。

## 二、网页搜索降级（两级触发）

### 触发条件

| 级别 | 触发时机 | 实现位置 |
|---|---|---|
| **① 零命中** | `search_knowledge` 返回"没有找到相关内容" | `_rag_search` 节点 |
| **② 模型自认不足** | 答案开头出现「知识库中没有 / 没找到 / 没有专门 / 资料不足」等表述 | `_answer` 节点 |

第 ② 级才是你真正要的：**不是等检索完全为空，而是模型判断"资料不够"时就补搜一次再重写**。

### 二级降级的流程

```
生成答案
   ↓ 检测到"我没找到"（去掉 markdown 符号后再匹配）
   发 reset 事件（清空前端已流式显示的草稿）
   ↓
调用 web_search（360 搜索）
   ↓
把结果作为 SystemMessage 追加，并要求「重新给出完整回答」
   ↓
重新生成 → 推送最终答案
```

关键细节：**必须先发 `reset`**。流式模式下第一版草稿已经推给前端了，
如果不作废，用户会看到两段答案拼在一起。

### 搜索源选择（实测）

| 引擎 | 结果 |
|---|---|
| 百度 | ❌ 触发安全验证（反爬） |
| DuckDuckGo / SearXNG | ❌ 本机网络超时 |
| cn.bing | ⚠️ 可用，但中文查询被泛化成"docker 教程"这类无关结果 |
| **360** | ✅ **中文相关性最好，且结果块里带 `data-mdurl`（真实地址）** |

所以：**360 为主，Bing 兜底**；配了 `TAVILY_API_KEY` 会优先用正经 API。
另外过滤掉 360 的翻译/直达卡片（`fanyi.so.com`、`ai.so.com`、`so.com/link`）——那些不是内容页。

### 来源标注（很关键）

网页结果在给模型时带明确抬头：

```
【网络搜索结果】（来源：360 (1.3s)，非内部知识库，引用时请注明这是网上资料）
[W1] Docker Desktop 卡死在 Starting the Docker Engine 问题解决
    链接: https://blog.csdn.net/...
    摘要: ...
```

system prompt 里也加了硬约束：**引用网上内容必须写"来自网络搜索"，不许伪装成内部文档路径**。

### 实测

问一个知识库确实覆盖不全的问题：

```bash
.venv\Scripts\python.exe scripts\agent_demo.py "Docker Desktop 卡在 Starting，官方完整排障步骤有哪些？" --yes
```

Trace 变成 4 步：

```
[1] plan
[2] tool → search_knowledge            1233ms
[3] tool → web_search                   ← 模型判断知识库不足，降级
    思考: 模型判断知识库不足，降级到网页搜索
    观察: 【网络搜索结果】（来源：360 (1.3s)...）
[4] answer  10786ms
    思考: 基于检索结果生成回答（已补充网络搜索）
```

耗时从 5.5s 涨到 12.2s（多了一次搜索 + 一次重写），换来的是完整的排障步骤。

## 三、路由关键词补充

你那次对话里，说「确认提交」之后却走了 `route=rag`，导致模型只能空谈"我需要调用工具"。

原因：`classify()` 只认「工单/建单/升级/SLA」等词，没认"确认类"的后续指令。

已补：`确认提交`、`确认建单`、`提交吧`、`就建`、`建吧`、`好的，建`、`同意提交`、`结单`、`resolve`。

实测：

```
'确认提交'                     -> agent   ✅
'就建吧'                       -> agent   ✅
'好的，建'                     -> agent   ✅
'Docker 卡在 Starting 怎么办'  -> rag
```
