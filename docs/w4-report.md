## 二、四个结论

### ① 查询改写是最大的「排序」改进

E3 → E8：MRR **0.436 → 0.509（+7.3pp）**，hit@1 **0.250 → 0.367（+46%）**，而 hit@5 不变。

为什么：中文 query 在 BM25 上原本**零命中**（E2 已证明），所以混合检索实际退化成了纯向量。
改写后 BM25 真正参与进来，它命中的往往是**标题级精确匹配**（"port already allocated" 直接对上 `Ports` 页），
这类命中会把正确文档顶到第 1 名——所以 hit@1 涨得比 hit@5 多。

代价：多一次 LLM 调用，延迟 201ms → 692ms。

### ② 排除 release-notes 是最大的「覆盖」改进，而且几乎免费

E8 → E10：hit@5 **0.733 → 0.783（+5pp）**，recall@5 0.497 → 0.525。

原因在失败案例里看得很清楚：q001（装完起不来）、q005（升级后容器消失）、q010（安装失败原因）
Top-3 全部召回 `manuals/desktop/release-notes.md`。这类页面把每个版本的每个功能都提过一遍，
**对几乎任何 query 都有表面相关性**，是典型的"万能吸铁石"。

单独验证：E1 → E11（只加排除、不加改写）也能从 0.650 涨到 0.700。
**这是纯数据清洗带来的 +5pp，比调 RRF 参数（±1.6pp）和上重排（−5pp）都划算。**

### ③ 重排（gte-rerank-v2）在跨语言场景下没有收益

| 对比 | hit@5 | MRR | 延迟 |
|---|---|---|---|
| E3 → E4（候选 20） | 0.733 → 0.667 ❌ | 0.436 → 0.437 | +550ms |
| E5（候选 50） | 0.683 ❌ | 0.439 | +890ms |
| E8 → E9（改写后重排） | 0.733 → 0.733 | 0.509 → 0.478 ❌ | +472ms |

三个配置、两次扩大候选，**重排都没有把 hit@5 拉回来**，只略微改善 nDCG（E4 0.557 > E3 0.533）。

推测原因（W5 可验证）：
- gte-rerank 是 (中文 query, 英文 chunk) 的跨语言打分，效果弱于 embedding 的语义对齐；
- 我们的 chunk 带面包屑前缀、长度约 200 token，重排模型被前缀噪声干扰；
- 重排把"整体相关性"排好了，但"是不是这个具体问题"判断不准，于是把精确匹配的条目往下压。

> **这是一个有价值的负结果**：面试官常问"你为什么不加重排"，
> 你现在可以答："我试了，候选 20 和 50 都试过，在跨语言场景下 hit@5 损失 5–6.6pp、延迟涨 4 倍，所以最终没上。"

### ④ RRF 的 k 不敏感

k=20 / 60 / 100 的 hit@5 分别是 0.733 / 0.733 / 0.717，MRR 0.442 / 0.436 / 0.437。
**差异在噪声范围内**。这个参数不值得花时间调，用默认 60 即可。

## 三、最终方案：E10

```
召回：向量 Top50 + BM25(改写后) Top50
融合：RRF k=60
过滤：排除 release-notes / previous-versions
输出：Top5
（不做重排）
```

指标：hit@5 **0.783**、hit@1 0.400、MRR 0.553、nDCG@10 0.600、延迟 721ms。

### 延迟还能怎么优化（W5 前可选）

| 手段 | 预期 | 风险 |
|---|---|---|
| 改写换 `qwen-turbo` | 692ms → ~400ms | 改写质量略降 |
| 改写结果缓存（已有） | 重复问题 0 成本 | 只对热点有效 |
| **仅当 BM25 零命中时才改写** | 大多数题省一次调用 | 实现复杂，收益待测 |
| 改写与向量检索并行 | 省 ~200ms | 需异步改造 |

## 四、仍然失败的 13 题，两类原因

### A. 标注太窄（不是检索的错）

- **q029**「磁盘被占满怎么清理」：召回了 `manuals/engine/.../pruning.md`（正确内容），
  但我的 gold 只标了 `troubleshoot`。
- **q045**「Windows 敲 docker 找不到命令」：召回了 `troubleshoot/topics.md`（正确内容），
  但 gold 只标了 `windows-install` 和 `faqs`。

> 这说明当前 0.783 是**偏保守**的数字，真实效果可能略好。
> 但也提醒：**gold 标注的松紧本身会影响结论**，W5 前应该复核一遍这 13 条。

### B. 真正的数据/检索缺口

- **q001/q005/q010** 仍受 release-notes 残留影响（部分已缓解，但 `manuals/engine/release-notes` 之外的版本页还在）
- **q022 WSL2 端口映射**、**q026 vmmem 内存**：中文表述与英文术语差距太大
- **q041 permission denied**：召回了一堆无关页，说明 `engine/install/linux-postinstall` 的 chunk 措辞不含"permission denied"

## 五、W4 学习清单（约 3 小时）

| 主题 | 时长 | 关键点 |
|---|---|---|
| 消融实验设计 | 1h | 一次只改一个变量；对照组必须是上一版最优 |
| 为什么负结果有价值 | 0.5h | "我试过但没用"比"我用了"更有信息量 |
| 评估指标的选择 | 1h | hit@k 看覆盖、MRR 看排序、nDCG 看整体、recall@k 看多跳 |

2. 为什么"排除 release-notes"能带来 +5pp，而这只是一个 if 判断？

4. RRF 的 k 从 20 调到 100 几乎没变化，说明什么？什么样的系统会对 k 敏感？
