# 简历项目描述：dockerhelp-agent

> 格式对齐你给的第一份（中医知识检索增强问答系统）：
> `时间 + 标题 + 角色` → `项目介绍` → 4~5 条带硬指标的要点。
> **所有数字都可用 `scripts/run_eval.py` / `scripts/selfcheck.py` 复现**，面试被追问不会翻车。

## 主版本（推荐）

```
2026.03-2026.06   Docker 场景 IT 服务台 Agent（检索增强 + 工具编排）      项目负责人

· 项目介绍：面向 Docker 容器场景构建可评测、可观测的服务台 Agent，将中文提问映射到英文官方文档
  与历史工单，输出带出处引用的处置建议；以工具编排承接查 SLA / 建单 / 结单，并用人工确认闸门
  约束写操作风险，全链路 Trace 支持回放与量化评测。

· 自建混合检索链路：把 932 篇官方文档按结构感知切成 8,788 个 chunk（标题路径作 breadcrumb 前缀
  提升长文召回），向量（text-embedding-v3）与 BM25（jieba 混合分词）经 RRF(k=60) 融合，并按
  文档路径黑名单剔除 release-notes 类"磁铁文档"；在 65 条中文评测集（gold 按文档路径前缀标注）上
  hit@5 由 0.650 提升至 0.767，Recall@5 0.533，P50 215ms。另以 11 组消融验证跨语言重排为负收益
  （-6.6pp），据此否决该方案而非盲从"RAG 最佳实践"。

· 构建路由式 Agent：基于 LangGraph StateGraph 实现确定性意图路由 + ReAct 循环，挂钩 6 个工具
  （检索 / 查工单 / 查 SLA / 记事实 / 建单 / 结单）；写操作通过 interrupt() 暂停至 checkpoint
  等待人工确认，工具节点约束为"一次只执行一个"以保证恢复时副作用不重复；引入重复调用拦截、
  观察截断与 token 预算三项中间件，同一问题的 token 消耗由 17,208 降至 5,138（-70%）。

· 设计分层记忆：会话状态用 checkpoint（thread_id）续接上下文，长期事实与事件存 Redis
  （user_id 隔离、事件 90 天 TTL，命中失败自动回退 SQLite）；记忆块以 system prompt 注入而非
  拼接 messages，避免破坏 tool_call 与 tool 消息的配对结构，实现跨会话回忆客户等级与产品版本。

· 形成数据与评测闭环：工单结单时自动将「问题 + 解法」转为 cases/<id> 文档，复用同一套切片与索引
  流程，使内部处置经验可被检索（同类问题 Top-1）；知识库零命中或模型自判资料不足时两级降级至
  网页搜索并强制标注来源；沉淀 35 项单测、9 项 API 验收与 8 个场景回归保障交付质量。
```

## 三个大概率被追问的问题

**Q：为什么不做重排？**
> "我做了，E4 加了重排 hit@5 从 0.733 掉到 0.667。原因是 query 是中文、文档是英文，
> cross-encoder 跨语言打分噪声大，还会把原本排对的文档压下去。所以我保留了消融数据，
> 但没有把它放进最终链路。"

**Q：8,788 个 chunk 怎么切的？**
> "结构感知切分：先按 markdown 标题层级切 section，再在 section 内按 token 上限打包，
> 每个 chunk 前面拼标题路径（breadcrumb）。这样检索时不会丢掉'它属于哪一节'这个信号。
> 过短的尾部碎片会丢，但整篇都短时（比如工单案例只有 100 多 token）不丢——这里踩过坑，
> 一刀切会把整篇丢光。"

**Q：写操作的安全怎么保证？**
> "两层：一是 interrupt()，图执行到写操作就暂停，参数落进 checkpoint，就算绕过界面直接调 API
> 也会被拦住；二是工具节点一次只执行一个调用——因为 interrupt 恢复时节点会重跑，
> 一次执行多个会导致副作用重复。"

## 使用建议

1. **时间**：按你实际投入的时间改（我是按 3 个月写的）。
2. **角色**：如果是个人项目写"项目负责人"没问题；如果作为课程/实训项目，可改"核心开发"。
3. **顺序**：简历里这条建议放在**第一个**——它比纯 RAG 项目多了 Agent 编排、人工闸门、数据闭环三层，
   而这三层正是 Agent 岗位 JD 里高频出现的词。
4. **删减原则**：如果版面只放 4 行，删掉"数据与评测闭环"那条的第 3 句（测试相关），
   保留检索、Agent、记忆三条——它们是面试官最可能深挖的。
